# Техническое задание (Task Document): AI Code Editor (Rust + TS)

## 📌 Описание проекта
Разработка собственного высокопроизводительного редактора кода / IDE со встроенными автономными ИИ-агентами. 
Основной упор на скорость (ядро на **Rust**), расширяемость (система плагинов на **TypeScript**) и SaaS-модель монетизации (оплата за **Pro-подписку** вместо оплаты за токены).

## 🏗 Архитектура и Стек
- **Core (Локальный движок):** Rust (максимальная производительность, безопасная работа с памятью, ФС, многопоточность).
- **Backend (Серверная часть):** Rust (Axum или Actix-web), PostgreSQL (БД), Redis (Rate Limiting и кэширование).
- **Plugin Runtime (Среда выполнения):** Rust + `deno_core` (движок V8 для безопасного запуска TS/JS кода внутри Rust).
- **Frontend/Плагины:** TypeScript (написание логики агентов, интеграций, UI).
- **Billing (Оплата):** Stripe (подписки).
- **AI (ИИ Мозг):** Model Context Protocol (MCP), интеграция с LLM (OpenAI/Anthropic/Gemini) **строго на стороне бэкенда**.

## 📋 Task List (Дорожная карта)

### Фаза 1: Разработка ядра и бэкенда (Rust)
- [ ] **Task 1.1:** Инициализация локального движка на Rust. Настройка многопоточности и базового управления состоянием приложения.
- [ ] **Task 1.2:** Реализация интерфейса взаимодействия с файловой системой (чтение, запись, поиск по проекту, отслеживание изменений файлов).
- [ ] **Task 1.3:** Разработка серверного API на Rust (Axum/Actix). Настройка WebSocket-соединения для реалтайм-общения движка с сервером.
- [ ] **Task 1.4:** Проектирование БД (PostgreSQL) + `sqlx` или `Diesel`. Создание таблиц пользователей, сессий и токенов.

### Фаза 2: Среда выполнения плагинов (Мост Rust <-> TS)
- [ ] **Task 2.1:** Интеграция `deno_core` в ядро на Rust для создания безопасной песочницы (isolate) для запуска JavaScript/TypeScript.
- [ ] **Task 2.2:** Разработка биндингов (ops). Проброс функций Rust (работа с ФС, сетью, командами редактора) в контекст плагинов.
- [ ] **Task 2.3:** Создание TypeScript API для плагинов (аналог `vscode.*` API). Документация методов.
- [ ] **Task 2.4:** Реализация менеджера плагинов (загрузка, изоляция процессов, установка плагинов из маркетплейса).

### Фаза 3: Система автономных ИИ-агентов
- [ ] **Task 3.1:** Разработка логики на бэкенде для безопасного обращения к API нейронок. API-ключи должны храниться только в `.env` на сервере.
- [ ] **Task 3.2:** Создание базового TS-плагина "AI Copilot/Agent". Разработка интерфейса чата внутри движка.
- [ ] **Task 3.3:** Реализация системы инструментов (Tools/Function Calling). Агент должен уметь отдавать команды: `read_file`, `write_file`, `list_dir`, `run_terminal_command`.
- [ ] **Task 3.4:** Механизм применения кода: ИИ отправляет diff (разницу), плагин показывает предпросмотр (Accept/Reject), движок на Rust физически меняет файл.

### Фаза 4: Биллинг и Pro-подписка (Отвязка от токенов)
- [ ] **Task 4.1:** Интеграция Stripe на бэкенде. Создание продуктов подписки (например, Free и Pro tier).
- [ ] **Task 4.2:** Настройка вебхуков Stripe на сервере (автоматическое изменение статуса пользователя при оплате).
- [ ] **Task 4.3:** Защита от абьюза: реализация Rate Limiting (через Redis). Установка "мягких лимитов" (например, 500 запросов в день на Pro-аккаунте), чтобы не уйти в минус по API-счетам от LLM.
- [ ] **Task 4.4:** Авторизация в движке (Login via Browser) и блокировка генерации кода, если нет активной Pro-подписки.

### Фаза 5: Внешние интеграции (Cloud Code & Cloud Design)
- [ ] **Task 5.1:** Разработка отдельного TS-плагина для интеграции с Cloud Design (работа с дизайн-токенами, компонентами).
- [ ] **Task 5.2:** Разработка TS-плагина Cloud Code (синхронизация, деплой, облачная инфраструктура).
- [ ] **Task 5.3:** Вывод API в паблик, чтобы комьюнити могло писать свои плагины на TS для вашего Rust-движка.
